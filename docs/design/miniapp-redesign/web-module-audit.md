### 0.2 一句话判断

网页端已经长成"**行情数据库 + 分析工作台**"；小程序的定位是"**今天做什么**"的决策工具。两者可以共用计算内核与 444 项核心数据，但**不能共用同一套信息架构**。

- **留在网页**：散点/箱线、完整 A/B/C 证据、流动性/活跃度、Excel/CSV/PNG 导出、外部工作台。
- **删掉**：小程序里的重复技艺页、5 秒启动广告页、散点/箱线入口。

## 1. 审核方法

按 V1 设计的五条原则逐项打分：

1. **一屏一问**：这个模块能否用一个问题概括？
2. **频次 × 决策价值**：玩家每天/每周会不会用？用完会不会改变行为？
3. **移动端操作**：是否需要表格、横向滚动、多选、长表单？能否在 44px 触控区内完成？
4. **数据/包体**：需要多少 JSON？是否必须离线？能否放云端/分包？
5. **数据可信**：是否依赖完整报价证据、A/B/C、历史节点？这些数据小程序是否拿得到？

打分结果分为四档：

- **P0 移植**：进 4 Tab 主流程，V1 必做。
- **P1 精简移植**：进二级页或详情页，砍掉桌面交互。
- **P2 延期**：有价值，但需要新数据/新页面/新计算，V1 不做。
- **网页专属**：桌面能力，移动端不做。

### 2.1 重点判断

#### 为什么 672 项行情目录放进分包，而不是主包

- 672 项 = 家园 294、强化 138、消耗品 115、材料 62、包裹 17、挂件 16、其他 14、坐骑 10、宝箱 6，**全部不被 251 条配方引用**，只做查价/记价。
- 按你的确认，它们已加入微信 **分包 `market`**：搜索 + 分类 + 记价，不进入「今日/排行」的收益计算。
- 它们只用于"查价"，不参与"今天做什么"的收益计算；小程序没有第 5 个行情 Tab，放进价格库会把 444 行的维护任务变成 1116 行的数据库。
- 包体：如果全塞主包，1116 项完整目录 minify 后约 618KB，比 444 项目录多约 350KB，主包会从 1.57MB 推到 1.9MB+，直接超过微信 1.5MB 代码质量线。
- 分包方案：主包仍是 444 项 / 1.57MB；行情目录分包约 **0.19MB**（672 项元数据 + 4661 条本服报价），远低于微信单个分包 2MB 上限。
- 已落地：价格库顶部「行情目录」入口 → `market` 分包页，支持搜索、分类、记价；手动价只存本机，不参与收益。

#### 为什么 A/B/C 只做"精简"而不做完整移植

- 网页 `audit-data.js` 744KB，包含 17 服 × 251 配方的证据、薄价、持续性、自产链；完整 UI 是表格 + 多级 tooltip，手机上一屏放不下。
- 小程序已有 `landability.json`（24KB）提供本服 A/B/C 计数与前 5 名；V1 设计要求"只看价格齐全"，不把 A/B/C 作为默认口径，避免和页面的"理论收益"数字冲突。
- P2 可生成**紧凑评级表**（每服 A/B 配方 id + 徽标），只做"可做/谨慎"筛选，不改收益口径；完整证据仍留网页。

#### 为什么制作收益 P2

- `profit.js` 解决的是"材料买不到时自造、自造精力算进去、跨服能不能做"的专家问题，需要材料链、路径、跨服表、历史曲线。小程序配方详情已有成本/利润/材料三块；V1 再加一层会重新变成"信息密度过高"。
- P2 可在配方详情加一个折叠块：`购买 / 自造 / 混合` 三种路径的成本与额外精力；完整模块和 Top10 留网页。

### 3.6 发现的链路 Bug（已修）

```
网页价格机器人
  update-jx3-prices.mjs --web-only
    ├─ 写 assets/data.js          ✅
    ├─ writeData() 直接 return    ❌ 小程序 catalog.json 不更新
    └─ build-remote-prices.mjs    ❌ 读的是旧小程序 catalog
```

- 结果：网页 23:08 更新了 1116 项，小程序包内还是 17:12 的 444 项；云端行情由旧目录生成，也旧。
- 修复：
  1. `scripts/lib/miniapp-catalog.cjs` 统一生成 444 项核心目录；
  2. `update-jx3-prices.mjs --web-only` 仍写小程序核心目录（只跳过小工具 zip）；

  5. `remotePrices.js` 增加时间戳保护：云端旧于包内时不写入；
